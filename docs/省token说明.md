# 省 token 说明(给使用工作台的同事)

2026-10-22 加。背景:截图说明修改、一次给很多参考图、nano banana 生图、Claude 连 Figma 改素材——这些都会让 token 用得很快。现在**不用改你的习惯**:仓库里的 skill `save-tokens`(`.claude/skills/save-tokens/`)会让 Claude 自动用更省的方式做事,再加一个「提前自动压缩」。

## 为什么会快

- **图片一进对话就一直在**:一张截图或参考图约 1000–1600 token,之后每一轮回复 Claude 都要带着它重新处理。一次 10 张参考图 ≈ 1.5 万 token,而且一直占着。
- **生图结果如果回到对话里**,每张又是一两千 token;让 Claude"看看效果"再改,图越积越多。
- **Figma 截图 / 读整页设计**,每次几千到上万 token;每改一步截一次图,很快就满。
- **一个对话从头做到尾**,前面所有图片都还在。

## Claude 现在会怎么做(自动)

| 场景 | 以前 | 现在 |
|---|---|---|
| 生图 / 改图 | 结果图回到对话里给 Claude 看 | 结果直接存文件,Claude 只拿到路径,用"发文件"给你看(不占它的上下文);多张只看一张对比图(你本机配好的 nano banana 照常用;它会把图回到对话里的话,改用 `dev/lite/nano.py`) |
| 一次给很多参考图 | 每次都重新看图 | 第一次看完写成「风格卡」(`docs/风格卡/`,几百字),之后引用文字;参考图放文件夹里,生图时脚本直接读文件 |
| 比较很多张图 | 一张张看 | `dev/lite/sheet.py` 拼成一张带编号的小图(32 张 ≈ 1 张的 token) |
| 截图说明修改 | 改一步截一次图确认 | 一条消息里的修改一次做完;要截图核对时先缩小、裁边(`dev/lite/shot.py`) |
| Figma | 读整页、频繁截图 | 先读结构(很便宜)找节点,只在最后验收时截改动的那一小块 |
| 对话越来越长 | 要到约 97 万 tokens 才自动压缩,之前每一轮都带着前面所有图片 | 装了「提前自动压缩」后到约 20 万就自动压缩;压缩前 Claude 先把进度写进进度卡,压缩后自动读回来接着做,不用你开新会话 |

## 你要做的(只有一次)

1. 拉取仓库最新代码(skill 跟着仓库来,不用另外装)。
2. 让你的 Claude 运行一次:`python dev/lite/install_token_saver.py`(装「提前自动压缩」,只改你这台电脑的 Claude 设置,改之前会备份;想换压缩线就加 `--window 300000`,不想要了就 `--uninstall`)。装完新开一个会话生效。
3. 之后照常用。nano banana 用你本机已经配好的就行。

## 想再省一点(可选,不强求)

- 截图时只框要改的那一块,不截整屏。
- 一批参考图放进 `docs/风格卡/<名字>_参考/` 文件夹,告诉 Claude 文件夹名,不用一张张粘贴。
- 截图后不粘贴,直接跟 Claude 说「看剪贴板」,它会先缩小再看。
