# Figma 插件「BUD UI Studio」(导出 / 导入)

在 Figma 里把选中的界面(图层结构 + 切图)导出成一个 `.budfig.json` 文件,交给 BUD UI Studio「导入插件包」还原成可编辑的界面,再配动效、导出 Unity 预制体。

**全程在本机完成,不调用 Figma 接口,不受账号席位的调用额度限制**(查看/协作席位也能用)。

## 安装(每台电脑一次,约 1 分钟)

1. 打开 **Figma 桌面版**(网页版不能装开发插件)。
2. 打开任意设计文件 → 左上角主菜单 → **Plugins(插件)→ Development(开发)→ Import plugin from manifest…(从清单导入插件)**。
3. 选择本文件夹里的 `manifest.json`。

装好后,插件出现在 **Plugins → Development → BUD UI Studio**,有两个命令:「导出给工作台」和「从工作台导入」。(2026-10-10 以前装过的,要在 Development 里移除后按上面重新导入一次 manifest,菜单才会出现。)

## 从工作台导入(工程 → Figma 图层)

把工作台工程(`.budui.json`)还原成可编辑的 Figma 图层:每个工程一个分区(Section),每个界面一张 2436×1125 画框;容器 → Frame,切图 → 图片图层(拉伸铺满,和 UGUI 一致),文字 → 可编辑文字,默认隐藏的节点导入为隐藏;每个图层的工作台标识 / 点击 / 动效存在 pluginData `budui` 里。一起选的 PNG 放进「参考图」分区。同名分区再导入会替换。

1. 先装字体(只要一次):思源黑体 CN Heavy / Medium / Regular、Montserrat Black / Bold / Medium,文件在主工程 `Assets/Arts/Font/`(`exports/figma_lijixiantest/字体(先双击安装)/` 里有一份)。没装的话插件会用替补字体并在结果里列出来。
2. 在 Figma 里新建或打开目标设计文件 → Plugins → Development → BUD UI Studio → 从工作台导入。
3. 填页面名(默认 `lijixiantest`,没有就新建)→ 选文件(可多选 .budui.json 和 .png)→ 导入。

回归测试:`node dev/plugin_import_selftest.js`(模拟 Figma API,用真实工程检查图层数、画框、图片、文字、隐藏、标识、同名替换)。

## 使用

1. 在画布上选中要做的**界面**(一个或多个 Frame);也可以直接选中**整张总览画板**,插件会自动列出里面所有 2436×1125 的界面。前提:界面是总览画板的直接子层,比例接近 2436×1125;总览画板如果是 Section,插件展不开,要直接选中里面的界面。
2. 运行插件:右键 → Plugins → Development → BUD UI Studio 导出。
3. 勾选要导出的界面 → 点「**发送到工作台**」(不需要 Figma Token、不用下载文件):插件把整包 POST 给本机工作台服务 `POST /api/bridge/screens`(配对码校验,存到 `exports/bridge_screens/`,只留最近 5 个),工作台页面开着时 3 秒内自动弹出「收到 Figma 发来的…导入到当前任务?」,确认即导入。
   - 第一次要展开「连接设置」:服务地址默认 `http://localhost:8791`,配对码在工作台「资源批处理」页签顶栏(与资源批处理命令共用,存在 Figma clientStorage `budui_bridge`)。
   - 报「连不上」= 工作台服务没开(双击桌面「BUD UI Studio」);「配对码不对」= 重新填;「服务是旧版」= 重启服务。
   - 备用:点「下载 .budfig.json(备用)」存成文件,再在工作台点「**导入插件包**」选这个文件。
4. 工作台里确认导入 → 勾选要导入的界面(默认全选,说明页不勾,主页自动识别)→ 一次导入为一个模块:图层、文字、位置自动还原,每页按图层角色配好动效和交互,并连好页面跳转。

整张总览画板可以一次导出成一个包。设计稿改了就重新导出:新增的界面导入时选「补充到当前模块」(只加新界面,已有的同名页不会更新);要更新已有的某一页,只导出那一个界面,在工作台先切到那一页,导入时选「替换当前正在编辑的页面」;要全部重建就选「重新导入为新模块」(手动改过的设置会丢)。

## 它导出了什么

| 图层 | 处理方式 |
|---|---|
| 思源黑体 / Noto Sans SC / 苹方 / 微软雅黑 / Montserrat 的纯色文字 | 保留为**可编辑文字**(进 Unity 后是 Text 组件,可由服务端数据替换) |
| 其它字体、渐变字、带描边/投影的文字 | 渲染成图,保证视觉一致 |
| 含文字的分组 | 保留为分组,里面的图层逐个处理 |
| 不含文字的分组、图形、图片 | 整体渲染成一张切图 |
| 开了"裁剪内容"且内容超出的分组 | 在 Studio 里还原为可滚动区域 |
| 隐藏的图层 | 不导出 |

## 常见问题

- **导入清单时提示插件 ID 无效**:在 Figma 里 Plugins → Development → **New plugin…** 新建一个空插件,把 Figma 生成的 ID 复制到本文件夹 `manifest.json` 的 `"id"` 字段,再重新导入。
- **运行时提示没有权限**:插件只读取、不修改文件。如果仍然不能运行,截图发给维护者。
- **导出很慢或文件很大**:每个 2436×1125 界面通常只有几 MB;一次导出十几个界面会到几十 MB,属于正常情况。

## 维护(改规则前必读)

切图规则(哪些图层保留为文字/分组、哪些渲染成图)在 `code.js` 的 `planRenderIds` 和 Studio 的 `buildScreenFromFigma` 里各有一份,**必须保持一致**;改动时两边同步修改,并把两边的规则版本号(`RULES` / `PLUGIN_RULES`)一起升级。改完运行 `node ../dev/plugin_selftest.js` 做回归测试(在本机模拟 Figma 环境,约 1 秒)。
