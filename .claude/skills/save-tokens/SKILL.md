# 省 token 的工作方式

背景:图片一进对话就一直占上下文(一张约 1000–1600 token,之后每一轮都要带着它),Figma 截图和整页设计上下文每次几千到上万 token。用户习惯截图说明修改、一次给很多参考图——**不要求用户改习惯**,由你按下面的方式做。工具在 `dev/lite/`(Python 用 `C:\Users\<用户>\AppData\Local\Python\bin\python.exe` 或 PowerShell 里的 `python`;Git Bash 里的 `python` 可能是商店占位程序,什么都不做)。

## 1. 图片:看一次,之后只用文字和编号

- 看过的图之后用文字或编号指代,不要再 Read / 截一次同一张图。
- 要同时比较多张**本地**图片(参考图、几版生图结果、一批切图),先拼成一张再看:
  `python dev/lite/sheet.py 图或文件夹 …` → 输出一张带编号的小图(32 张 ≈ 1 张的 token)和「编号 = 文件名」对照,之后用编号说话。
- 要自己截图 / 看截图文件核对时,先瘦身再 Read:`python dev/lite/shot.py 图 [--crop x,y,w,h]`(裁边、缩到长边 800);用户说「看剪贴板」就 `python dev/lite/shot.py --clip`。
- 要逐张看很多图才能下结论的活(从 20 张里挑最像的、逐张检查切图),交给子代理(Agent 工具),主对话只收文字结论。

## 2. 参考图 → 风格卡

用户一次给很多参考图时:看完第一遍就写风格卡 `docs/风格卡/<名字>.md`(格式见 `docs/风格卡/README.md`:主色 HEX、材质、光影、描边、元素、禁止项、提示词底稿,≤20 行),请用户把原图放进 `docs/风格卡/<名字>_参考/`。之后生图、改图、讨论都引用风格卡文字和这个文件夹路径,不再重新看图。

## 3. 生图 / 改图(nano banana)

- 用户本机已经配好 nano banana 的 API。不管用哪种方式调用,都要做到:**结果直接存成文件(放 `exports/nano/` 下),对话里只留路径**;不要把图片或 base64 打到终端,不要 Read 生成的图去"看效果"。
- 给用户看结果:用发文件给用户的工具(如 SendUserFile)发过去——发文件不进你的上下文。几张一起看时先 `sheet.py` 拼成一张再发 / 再看。
- 现有调用方式会把图片回到对话里的话,改用 `python dev/lite/nano.py "提示词" --ref 原图或参考图文件夹 [--n 张数] [--name 名字] [--sheet]`(Gemini 原生接口,结果只存文件、只打印路径;Key 读 `dev/lite/nano.local.json` 或环境变量 `NANO_API_KEY` / `GEMINI_API_KEY`,中转地址改 `base_url`)。
- 参考图和要改的原图用文件路径传给生图脚本(脚本自己读文件,不经过对话)。

## 4. Figma

- 先 `get_metadata`(只有结构,便宜)找到要改的节点;`get_design_context` 只对具体的小节点用,不对整页 / 整个画板用。
- `get_screenshot` 只在用户要求或最后验收时用,只截改动的那个节点。
- 改完用 `get_metadata` 核对数值(颜色、尺寸、位置),不要每改一步就截图。

## 5. 用户截图说明修改时

- 已经发来的截图不要让用户重发。
- 一条消息里的所有修改一次做完,中间不截图确认;最后需要验收时只截一次、只截改动的地方。
- 回复保持短:不复述截图里的内容,不把大段工具输出贴给用户。

## 6. 进度卡 / 对话变长 / 换素材

- 进度卡:`exports/lite/进度卡.md`(不进仓库,≤15 行:做到哪、用的风格卡、关键文件路径、用户定下的修改要求、下一步)。
- 装了「提前自动压缩」(`python dev/lite/install_token_saver.py`,装在本机用户设置)的电脑:快到压缩线时会收到自动提醒——照常回答,同时更新进度卡;压缩后会收到提醒先读进度卡。不用让用户开新会话。
- 用户换了素材 / 任务时:更新进度卡,建议开新会话并给一句开场白(新会话读进度卡接着做)。
