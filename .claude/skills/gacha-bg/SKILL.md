# 扭蛋主题背景

每期扭蛋都要出一张和本期角色有关联的背景。背景就是一个舞台,唯一目的是凸显中间的角色模型:UI 版式固定(模板 = S18「圣羽降临」),舞台主题和道具每期随意,**只守构图节奏**(规范 §3:中心主背板框住角色 → 两侧道具群渐小渐虚 → 视线往中心收 → 地面托住角色)。不要在风格卡或提示词里给道具定死位置。
通用规范:`docs/扭蛋背景规范.md`(版式表、场景结构、配色目标、质感要求)。动手前先读它,不靠记忆。
同时按 `save-tokens` 技能处理图片:参考图只看一次,写成风格卡后就用文字和路径。

## 每期流程

1. **收素材,自动归档**:把用户给的图按用途拷进 `docs/风格卡/扭蛋_<期名>_参考/`,命名为 `角色设定_*`、`氛围参考_*`(构图节奏 / 氛围 / 精致度)、`质感参考_*`、`背景初版_待改`(有的话)。不要让用户自己整理。往期的 `氛围参考_*` 也可以拿来用。
2. **拆角色 → 写本期风格卡** `docs/风格卡/扭蛋_<期名>.md`(格式照 `扭蛋_虚拟歌姬.md`,≤20 行):
   - **先定气质**(10-29 虚拟歌姬踩过:白天户外乐队舞台配酷系数字偶像，用户说「不搭但说不出哪里」):用 3 个词写角色气质(如 酷 / 数字 / 夜场),再由它推出 **时段与天空、主光色、道具的世界**(虚拟偶像 = 全息屏、声波、光棒海，不是实体乐队)。场景的光色就是角色的颜色，角色站在最亮的那团光里。模板只管版式和 UI 可读性，不决定白天还是夜晚。
   - 角色识别色(HEX)、**造型语言**(硬朗机甲 / 圆润可爱 / 华丽古典……道具必须跟着走)、人设关键词。
   - 舞台主题：主背板做成什么轮廓(从角色元素**提炼**成一个大而简单的形状，不照搬角色身上的配件放大),两侧道具群是什么;不写坐标。
   - 背景配色：明暗跟气质走(明亮系照模板高调浅色;酷 / 夜场系在风格卡写明放宽亮部、暗部目标);本期主色相做主光和灯带;压重色和对比色各取什么。黑色只做细结构线，不要大黑块贴在模型身后。
   - 画风默认 2D 动漫插画背景;光是点缀,不满屏炫光。
   - 风格卡写完给用户看一眼要点(3–5 行),再出图。
3. **出图**:用 `gemini-batch-image` 技能,批量。
   - **先小样后正稿**:新的一期或方向没定时,先用 Nano Banana 2.1 出 4–6 张便宜小样只比方向(画风、光的强弱、道具多少),用户挑定后再用 Nano Banana Pro 出 4 张正稿。
   - 提示词 = 风格卡「提示词底稿」+ 版式句:`one large simple themed backdrop behind the empty center framing the performer like a halo, smaller prop groups on both sides getting smaller and softer toward the edges, lights along the top edge, stage floor with perspective lines leading to the center, calm smooth floor in front, clean sky in the upper left area, no text`。
   - 参考图用文件路径传:本期 `_参考/` 里的角色设定 + 1–2 张氛围参考(构图节奏)。模板干净背景只在要对齐明暗时带上。
   - 比例选最接近 2436:1125 的宽幅,出完等比铺满 2436×1125 并居中裁切。存到 `exports/gacha_bg/<期名>/`,对话里只留路径。
   - 有角色版:在选定的无角色版上做局部重绘,只改 character_slot 区域,别的不动。
4. **验收(必跑)**:`python dev/gacha_bg/gacha_check.py <图>`。
   - 有 ✗ 先修再交;! 写进交付说明。
   - 多张候选先 `python dev/lite/sheet.py exports/gacha_bg/<期名>/` 拼成一张发给用户挑,不逐张 Read。
5. **交付**:用发文件的工具把选中的图和 `_遮罩.png` 发给用户;用户要放进 Figma 的话,放在模板画板 951:2402 旁边。

## UI 件(标题 logo / 4 个奖励底 / 抽取 1 次 / 抽取 1 轮)

11-02 虚拟歌姬踩过：让 AI 在背景上整屏画 UI → 位置尺寸全跑、还自己画了个角色、改了背景，用户说「和定的规则不一样」。所以:
- **底图用游戏内截图**(用户给的、或背景 + 模型 + 现有 UI 的实机图),拉成 2436×1125 存 `exports/gacha_bg/<期名>/UI第N轮/游戏内截图_2436.png`。不用纯背景，不让 AI 重画整屏。
- **每件单独出图**:绿幕 #00FF00 底、居中、不带外发光(发光由脚本加);按钮不带字(字是程序文本，合成时用脚本写);奖励底留空。logo 的字 AI 会写错，逐字核对。
- **位置只取 `layout.json` 的 zones**(title / reward_tl… / btn_once / btn_round),用 `python dev/gacha_bg/ui_compose.py --dir … --shot … --prefix …` 抠图、缩进 zone、贴进截图出效果图和透明切图。不手填坐标，不让 AI 摆位置。
- 方向没定时，每个方向出一套单件、各合成一张效果图给用户比，不出整屏 AI 小样。
- **按钮要按本期主题重新设计造型**(11-02 第3轮拿圣羽降临按钮改色被否):只沿用组件尺寸 531×171 和内部内容(币 / 原价 / 现价 / 文字 / 角标);两个按钮成对出在一张图里保证造型一致,`ui3_compose.py` 用 `pair:图:0/1` 切开、只留最大块(去重影和飘件),外框强制正好 531×171(用户要求长宽和旧按钮一致:等比缩到高 171,只拉伸中间纯底色段),内容按底板外框自适应排,`--lead` 调左端装饰留白。
- **奖励底(角色格)照模板组件换皮**(11-02 第2轮自由设计的按钮 / 奖励底被说「不合格」):先用 Figma 连接器 `download_assets` 导出 S18 730:3575 的「扭蛋/抽取按钮」748:938(含原始底板、优优币)和「扭蛋/角色格」748:899,原件垫绿底当 Image 1,提示词写 "keep exactly the same silhouette … only re-skin";币图标、价格、文字、折扣角标由 `dev/gacha_bg/ui3_compose.py` 按组件偏移画。同时出一版 `recolor:` 原件直接换色当保底。
- **logo 用户指定了参考就整套套用字效**,只换字和色调;没指定才自己定方向。

## 常见问题(从「虚拟歌姬」初版总结)

- 整张图都是同一个饱和色 → 脚本「饱和色总量」✗。主色只上在灯带 / 霓虹边 / 舞台边,底色回到浅色。
- 道具又大又多、跟角色抢 → 角色身上的实物被照搬成了大道具。改成一个主背板框住角色,两侧道具缩小变虚。
- 道具跟角色不像一家 → 造型语言不一致(角色硬朗机甲,道具却圆润软萌)。风格卡写明造型语言,提示词点名 "angular / cut corners" 之类,并禁 "soft rounded toy shapes"。
- 写实、像真实场馆 → 提示词别写 3D render / specular / 真实材质细节;画风写 2D anime illustration background。
- 满屏光柱光晕泡泡 → 光要有主次:模型身后一团最亮、几道明确光束、四周略压暗;不是满屏都亮。
- 光收太狠、又白又淡 →「没氛围」。别写 restrained lighting,氛围来自光的层次 + 空气雾 + 前景虚化 + 主色配对比色。
- 背景和角色「不搭」→ 气质没对上(时段、光色、道具世界)。回到风格卡「先定气质」重推,不是调道具多少。
- AI 写的字会变形 → 背景不出字,标题和招牌字后期单独做。

## 改规范

版式或配色目标变了:改 `dev/gacha_bg/layout.json`,同步 `docs/扭蛋背景规范.md` 的表,然后用模板干净背景跑一次脚本,确认模板自己仍然全部通过。
